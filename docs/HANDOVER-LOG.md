## 决策记录

### 2026-10-11:被移除的供应商只隐藏,不删代码(#10)

彻底删除要动约 20 个供应商文件、全部语言文件和设置页约 700 行,之后每次同步上游都会冲突,上游新增的测试也引用了这些枚举成员。所以改为由 `ENABLED_SERVICE_PROVIDERS` 一处控制:型号列表过滤、设置页下拉框过滤、服务端接口返回 404。恢复一家供应商只需改 `app/constant.ts` 里的两个列表。

### 2026-10-11:`/api/proxy` 直接关闭,不做修复(#11)

这个代理只为插件服务,而所有者不使用插件。修复它需要加访问码校验和严格的域名匹配,并长期维护一段安全敏感的代码;关闭则没有后续成本。代价是插件功能整体不可用,所以同时用 `PLUGINS_ENABLED` 隐藏了入口。

### 2026-10-11:拒答换模型单独成一个 PR(#9)

它依赖带日期的 beta 请求头,是当时唯一可能在真实接口上被否决的改动,不应该拖住型号更新。合并后没有收到报错反馈,但所有者也没有明确确认过这四个型号在线上仍能正常回复。

### 2026-10-11:安全审计的结论

所有者怀疑项目里有流量变现或数据上报的暗门。审计结果:

- 没有广告代码,没有主动读写 cookie 的代码,没有发现把聊天内容或 key 发给统计服务的代码。
- 确实存在的:Google Analytics 默认使用上游的账号(#13 已处理);付费版推广及其点击统计(#13 已处理);页面加载时经第三方镜像 `ghp.ci` 拉取插件定义(#11 已处理)。
- 审计中另外查出两处安全问题:无鉴权的通用代理(#11)和无鉴权的 MCP 服务端函数(#12)。
- 范围:只审了仓库自身的代码,没有审计 npm 依赖的内部实现。
